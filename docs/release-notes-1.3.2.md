# SVWB Analyzer 1.3.2

這一版補上畫面擷取的實際狀態，讓「找到遊戲視窗」和「真的收到遊戲畫面」不再被當成
同一件事。

沒有資料庫變更，升級不需要任何額外操作。

---

## 改進

- **擷取狀態以第一張實際畫面為準。** 程式不再只因為找到遊戲視窗就顯示擷取正常；辨識
  引擎成功收到並解碼第一張畫面後，才會進入待機辨識狀態。
- **主視窗與 HUD 會顯示「等待畫面」。** 如果遊戲已被找到、引擎也已啟動，但 Windows
  尚未送入畫面，介面會顯示黃色警告，不再誤亮綠燈。
- **診斷包可以直接確認擷取流程。** `engine.log` 現在會記錄附加要求、附加成功、第一張
  畫面的原始解析度，以及結束時實際處理的畫面數量。
- **附加失敗會留下明確原因。** 權限、無效視窗 handle 或 Windows Graphics Capture
  無法啟動時，診斷記錄會包含失敗的 HWND 與錯誤訊息。

---

## 如何判斷是否擷取成功

到**設定 → 辨識診斷 → 匯出診斷包**，查看其中的 `engine.log`：

- 出現 `first frame received source=1920x1080 normalized=1280x720`，表示 1920×1080 畫面
  已成功進入辨識引擎。
- 只有 `attach succeeded`、沒有 `first frame received`，表示 Windows 接受了擷取要求，
  但沒有送入任何畫面。
- 出現 `attach failed`，後方訊息會指出附加失敗原因。
- `detached framesSeen=N` 的 `N` 是該次擷取工作階段實際處理的畫面數。
